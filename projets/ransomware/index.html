BadUSB & DFIR

Simulation d'attaque et Analyse Forensique

Développement d'un ransomware Python (AES/RSA) déployé par clé physique Raspberry Pi Pico RP2040, suivi du rapport de l'investigation numérique post-infection.

Contexte & Objectifs

Le but du projet

Développer mes connaissances en cryptographie appliquées au développement de malware dans un scénario réaliste pour m'entraîner à la réponse à incident et à la rédaction de rapport professionnel.


Technologies utilisées :

  • Langages : Python, Powershell, Bash
  • Outils Offensifs : Raspberry Pi Pico (BadUSB)
  • Outils Défensifs : Volatility 3, FTK Imager, KAPE

Attaque

Vecteur initial : Usurpation matérielle via BadUSB Type A

L'attaque repose sur l'usurpation d'identité matérielle (HID Emulation) via un microcontrôleur Raspberry Pi Pico (RP2040).
Reconnu par l'hôte comme un simple clavier standard, la clé contourne la sécurité de Windows 10 et exécute une séquence d'actions à grande vitesse :

  • Évasion : Désactivation de la protection antivirus via les paramètres Windows ('ms-settings:windowsdefender').
  • Furtivité : Fermeture ciblée du processus 'explorer.exe' pour masquer les fenêtres pop-up liées à l'insertion de l'USB.
  • Déploiement : Identification dynamique de la lettre du lecteur, copie du payload ('host.exe') vers le répertoire temporaire '\Windows\Temp', exécution puis suppression du fichier source.

La Raspberry Pi Pico (RP2040) utilisé pour l'attaque.


Ransomware Python (AES-CTR / RSA)

L'exécutable déployé est un ransomware fait main conçu en Python implémentant une cryptographie hybride. L'objectif est de cibler le dossier utilisateur (/Documents), de chiffrer et d'ajouter l'extension .crypted aux fichiers, et de déposer une note de rançon sur le bureau.

  • Chiffrement des données : Les fichiers sont chiffrés via AES en mode CTR (Counter). Ce mode nécessite un Nonce (Number used once) pour garantir que deux fichiers identiques auront une signature chiffrée totalement différente via l'effet d'avalanche d'AES.
  • Protection de la clé (PKCS#1 OAEP) : La clé symétrique AES est générée dynamiquement. Pour éviter sa récupération en mémoire, elle est immédiatement chiffrée avec une clé publique RSA 2048 bits embarquée dans le script.
  • Structure du fichier : Le ransomware modifie l'en-tête de chaque fichier cible en y concaténant directement le Nonce (12 octets) et la clé AES chiffrée (256 octets) avant d'écrire le corps du fichier chiffré.

Génération des clés

En amont de l'attaque, la paire d'asymétrie a été générée via OpenSSL :

Bash 
# Génération de la clé privée RSA (2048 bits)
openssl genrsa -out private.key 2048

# Extraction de la clé publique (à injecter dans le script Python)
openssl rsa -in private.key -pubout -out public.key

Note : Pour des raisons évidentes de sécurité, le code source du malware et le script du BadUSB ne sont et ne seront pas rendus publics.
